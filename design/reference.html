Colour tokens

Semantic, never raw. Each pairing is chosen for WCAG AA; UI-3 is a formal contrast pass on these values.

Automation status & emergency stop

The status pill sits in the header of every screen — the one thing a user must never be unsure of is whether the robot is posting. The stop is two clicks from anywhere and available to any member.

● Active ‖ Paused ▲ Needs attention

Status is icon + text + colour, never colour alone — so it reads for colour-blind users and in greyscale.

Job status — failed and unresolved never share a visual

failed means no request was ever issued. unresolved means we do not know whether it published — a request for a human decision, not an error, so it is never a red badge.

◷ pending ⇄ claimed 🔍 needs verification ✓ published ∅ failed — nothing sent ⤼ skipped ？ unresolved — decide →

Post preview — always labelled

Styled to resemble a Facebook post for honest fidelity, and marked a preview so it can never pass as real.

Secret input — masked, reveal-once, no copy

Stored and masked. There is nothing to reveal after saving — no screen ever shows a saved key again.

Composer — counts graphemes, never .length

A conjunct like ক্ষ and a multi-code-point emoji each count as one, the way a reader sees them. Edit the text and watch the counts.

graphemes – / 400–1400 naive .length – (wrong for Bangla) Bangla ratio – target 0.85 ± 0.05

States — a component is not done without all eight

Empty: “No posts yet — generate your first.” carries the next action, not an illustration.
Error: “Could not reach the AI provider. Your key is saved; we will retry at 02:30.” — what happened and what to do, never an upstream body.
Success: “Draft saved. 3 of 10 in your buffer.”
Disabled explains why, adjacently: a greyed Publish reads “Approve the draft first.”
